# 一致性判据（ConStory-Bench 中文网文移植）

**来源**：移植自 [Picrew/ConStory-Bench](https://github.com/Picrew/ConStory-Bench) 的
`prompts/timeline_plot.md`（MIT License）。原文为英文叙事判据，本文件把它转写为
中文网文语境，**并按网文特性重构了错误分类**（见下方「为何改分类」）。

**引入它做什么**：novel-forge 现有的连续性判定是**机检**的（`check-factconflicts.py`
查台账字段矛盾、`debt.py` 查伏笔压力）。但机检只能查「可结构化的矛盾」。
**读者真正会发现的矛盾**——「第三章说三天后到，第七章说走了半个月」这类
散落在正文里的时间/因果冲突——目前无任何覆盖。

本判据是**LLM-as-judge 的判据文件**：当你需要让模型审校正文一致性时，
按本文件的分类与约束产出结构化判定结果。

**它不替代机检**。机检跑得快、零成本、能拦确定性错误；本判据贵、慢、会有
误报。顺序永远是先机检，再按需用本判据。

---

## 一、四条硬约束（这是本判据的全部价值）

移植时必须原样保留这四条，它们是判据质量的来源：

| # | 约束 | 为什么重要 |
|---|------|-----------|
| **H1** | 每条矛盾必须附**原文精确引用 + 成对定位**（`exact_quote` + `location` + `contradiction_pair` + `contradiction_location`） | 让判定**可复核**。现有 gate 输出分数和密度比，出问题时无法定位到句|
| **H2** | 某类别无矛盾时，返回空数组 `[]` 是**完全正确**的答案 | 防假阳性。治「为了交差硬找问题」这个通病——这是 LLM judge 最常见的失效模式 |
| **H3** | **显式排除文学手法**：比喻、讽刺、戏剧性夸张、意识流、人物故意说反话，**一律不报为错误** | 中文网文大量使用夸张。若不豁免，误报率会高到无法使用 |
| **H4** | **存疑时偏向文学解读**（when in doubt, favor literary interpretation） | 判定歧义时的默认立场 |

H3、H4 对中文网文尤其关键。原文判据写的是英文叙事，中文网文的夸张密度
远高于英美文学——「一拳打碎山门」这种描写若不豁免，会淹没真矛盾。

## 二、错误分类（按中文网文重构）

原判据分6 类：绝对时间、时长、时间并行、无因之果、因果逻辑、废弃情节。
这个分类对中文网文不够用——网文的核心冲突不在「日历」，而在**境界/时间线/
伏笔/战力**。重构如下：

### C1 时间线矛盾
同一事件在正文里有两个互斥的时间说法。

**找什么**：同一趟路程给出两个时长；「三日后」与「半月后」对同一事件；
人物年龄与「修炼了多少年」对不上；某事件的前后顺序被后文颠倒。

> 网文特例：修炼/闭关时长是高频矛盾点。常见错误是「闭关三年」与后文
> 「三年后他出关时天下已变三年」叠加算成六年。

### C2 空间矛盾
人物在同一时刻出现在两个地方。

**找什么**：角色在城东与城北同时被目击；同一件物品同时在两处；
对话内容证明说话人不可能在现场。

> 网文特例：**分身/幻影/传送**类设定天然豁免。若正文确立了「分身」设定，
> 「两地同时出现」不报为矛盾——这是 H3 在网文语境下的具体化。

### C3 无因之果（**与现有 `debt.py` 互补**）
重要结果、能力、物品凭空出现，没有前置铺垫。

**找什么**：角色突然拥有未提及的能力；关键物品没有交代来源就出现主角手里；
新知识/新技能没有学习过程就掌握；剧情转折缺乏因果基础。

> **与 `debt.py` 的分工**：`debt.py` 算的是**已登记伏笔的压力**（该还哪笔债）。
> C3 查的是**根本没进台账的**无源之因。一个都没登记的能力突然出现，
> `debt.py` 永远看不到。

### C4 因果逻辑违背
结果与已确立的设定/常识相悖。

**找什么**：效果与所述原因不成比例（练了一章就秒杀化神期）；
因果断裂违反前文建立的世界规则；人物反应与已确立性格严重冲突。

> **排除**：「降智」不算C4。人物做出明显不理性的决策是**剧情需要**，
> 只有当它与前文明确的性格锚点直接冲突时才报。

### C5 废弃情节（**与现有伏笔表互补**）
引入的重要元素之后再未提及。

**找什么**：重要物件/谜团出现后再无交代；人物目标中途消失且无交代；
承诺的揭示、对峙、冲突从未发生；重要关系凭空断掉。

> **与 `debt.py` 的分工**：`debt.py` 查**台账里登记了但没还**的债。
> C5 查**压根没登记就断了**的线。

### C6 战力与规则矛盾
同一体系内的力量层级前后不一。

**找什么**：A -described 为「无敌」的角色被低阶角色击败；
同一境界的强度表现差异过大且无解释；功法效果前后不一致。

> 这是**中文网文特有**的一类，原判据没有。玄幻/仙侠的「境界体系」是网文
> 最大的设定资产，也是最常崩的地方——作者写着写着忘了某个境界的强度。

## 三、输出格式

每条矛盾按下述结构输出：

| 字段 | 填什么 |
|------|--------|
| `exact_quote` | 正文**原文**，不得改写、不得节选到改变含义 |
| `location` | 第几章第几段（可核查的位置） |
| `contradiction_pair` | 冲突的**另一方**原文 |
| `contradiction_location` | 另一方的位置 |
| `error_element` | 具体涉及的要素（如「路程时长」「闭关时长」「境界强度」） |
| `error_category` | `C1`–`C6` 之一 |
| `context` | 简述为何矛盾 |

**每个类别单独成组，无矛盾时该组为 `[]`**（H2）。

```json
{
  "C1_timeline": [],
  "C2_spatial": [
    {
      "exact_quote": "「我在城西的客栈等着，你快些来。」",
      "location": "第 12 章第 3 段",
      "contradiction_pair": "「城北的守卫说亲眼看见他进了城西的客栈。」",
      "contradiction_location": "第 12 章第 7 段",
      "error_element": "人物位置",
      "error_category": "C2",
      "context": "同一时刻城北与城西都有目击记录，无分身设定"
    }
  ],
  "C3_causeless": [],
  "C4_causal": [],
  "C5_abandoned": [],
  "C6_power": []
}
```

## 四、可靠性警告（务必读）

移植自 [cjj826/LongJudgeBench](https://github.com/cjj826/LongJudgeBench)（MIT，仅论文
无可运行代码）的核心结论：

> **长文本 judge 存在显著的跨场景可靠性缺口。rubric 与参考答案是有帮助的，
> 但并不总是充分。**

对本技能的实际含义：

1. **单次判定不算数**。判据给「通过」不代表没问题，给「有问题」也可能是误报。
2. **不要用判据放行交付**。它是**辅助信号**，不是门禁。真正的门禁是
   `forge.py gate` 与 `check-factconflicts.py` 的机检。
3. **误报成本要认**。一个 C1-C6 全空的报告**不构成质量证明**，只构成
   「本轮未发现明显矛盾」。汇报时不要写成「已确认无矛盾」。

---

## 五、修改约定

本文件是移植件。若要调整分类（C1–C6）或放宽/收紧 H1–H4：

- **H2（空数组合法）、H3/H4（排除文学手法）不可删**——删了误报率会失控
- 改 C 类定义必须同步改 `check-factconflicts.py` 的机检规则，否则两者口径分裂
- 每次改动在文件末尾追加一行：改动内容 + 依据 + 验证方式

**不要静默放宽**。放宽阈值与放宽机检一样，会把问题从「太吵」变成「查不出来」。
