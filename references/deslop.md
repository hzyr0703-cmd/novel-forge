# 去 AI 味操作规程

> `check-ai-patterns.js` 有 **29 类规则**（8 条 blocking / 21 条 advisory），每条阈值都以真实
> 中文网文语料校准（七猫 5584 章 + 知乎盐言 3983 篇 + 《万疆》20 章 + demo 20 章），
> 误报率已压至 0.4% 量级。
>
> **规则数是单一事实源**：本文与 SKILL.md 里的数字必须等于
> `node scripts/check-ai-patterns.js --list-review-classes` 的条目数。改规则先跑这条命令，
> 再改文档。v2.8 前本文自称「22 类全表」，实际漏了 6 条（`em-dash`、`reverse-not-is`
> 两条还是 blocking）——这就是「文档一套、脚本一套」的典型代价。
>
> **重要定位**：这是本地风格可读性门禁，**不是 AIGC 检测器评分**。功能性人味文本会被标为待审，
> 而不是被强制改写。没有任何外部检测器参与打分。
>
> **它管什么、不管什么**：`check-ai-patterns.js` 只管「像不像机器写的」；
> 「该有的东西有没有」（对话占比、爽点密度、感官、钩子轮换、**段长**）由 `spec_check.py` 管。
> 段长只在 `spec_check.py` 判（90 字 blocking + 每章 1 段 120 字豁免），本 lint 不再出
> `long-paragraph`——同一现象两种严重度等于没有标准（v2.8 删除）。

## 一、怎么跑

```bash
# 单文件（默认有 finding 即 exit 1）
node scripts/check-ai-patterns.js --check 正文/第001章.md

# 只看 blocking（忽略 advisory），门禁用这个
node scripts/check-ai-patterns.js --json --fail-on=blocking 正文/第001章.md

# 批量
node scripts/check-ai-patterns.js --fail-on=blocking 正文/*.md

# 改前存一份，改完对比（v3.0）：看是「修好了」还是「改过头了」
node scripts/check-ai-patterns.js --json 正文/第001章.md > /tmp/before.json
# ……改写……
node scripts/check-ai-patterns.js --diff=/tmp/before.json 正文/第001章.md

# 查看完整分类表（规则数与分类的唯一事实源）
node scripts/check-ai-patterns.js --list-review-classes
node scripts/check-ai-patterns.js --list-categories
```

输出格式：`文件:行:列: [级别] 类型 (分类): 改写建议 (原文片段)`

**`--diff` 为什么重要**：只有 gate 过/不过时，改完只能看到「blocking 归零」，看不到
「这个类型从 2 涨到 7」——那往往是这轮修法在制造新毛病。`--diff` 会直接点出来：

```
前后对比：7 → 3 处（blocking 2 → 0）
  type                           before  after    Δ
  em-dash (readability)               4      1   -3
  period-stutter (readability)        1      2   +1
注意：period-stutter 比改前更多——可能是这轮修法在制造新毛病，不是修好了。
```

## 二、blocking 规则（8 条，必须清零）

blocking = 表面形态确定，**就地改写即可，不需要判断**。

| 类型 | 形态 | 改法 |
|---|---|---|
| `hard-banned-word` | ①**段首/分句首**的突变副词族：忽然/突然/蓦然/猛然/骤然/霍然/倏然/陡然/猛地/腾地/冷不丁<br>②**程度副词紧接情绪形容词**：非常/十分/极其/极为/无比/格外/特别/异常/分外/极度/相当/太 ＋ 生气/意外/紧张/害怕/满意…<br>③很＋情绪词、内心充满/涌起、感到愤怒、恍惚 | 改成动作 beat 或可观察的后果；**换同义词不算改**。只扫引号外；句中「他忽然想起」、量词「十分之一」、否定式「不太高兴」放行 |
| `not-is-comparison` | 「不是A，而是B」 | 删掉否定铺垫，直接写后项；或改成动作呈现 |
| `reverse-not-is` | 「是A，不是B」（与上条同族，方向相反） | 删掉后置否定，直接写 A 的表现 |
| `voice-contrast` | 「声音不大…却…」 | 删音量铺垫，写声音落进场子的具体效果（谁停了手、哪排安静了） |
| `negation-parade` | 「没有X，没有Y」/「没X没Y只是Z」 | 删否定清单，直接写现场实际有什么，最多留一个最有信息量的否定 |
| `em-dash`（**条件**） | 破折号 `——` / `—` / `--`。只判**引号外**，且全章密度 ≥2/千字 才算 blocking | 打断→动作 beat；拖长音→省略；插入说明→逗号 |
| `trailer-ending` | 「没人知道/还没有结束/才刚刚开始/正朝着…压了过去」 | 结尾停在具体动作、画面或一句台词上，让事件自己挂住 |
| `trailer-summary` | 「这一夜注定…/这一切都结束了/命运的齿轮」 | 结尾设定要落成最后一个具体动作，别替读者盖章 |

> **`hard-banned-word` 的判据是位置，不是词表（v2.8）**：旧版只禁「忽然」不禁「突然」、
> 只禁「非常」不禁「特别」，两句语义、节奏、画面完全相同，门禁把 a 判死、把 b 判活。
> 模型学到的是「忽然→突然」的替换表，而不是「用动作起跳」——门禁在奖励更假的文字。
> 现在整族按位置判：突变副词只在**段首/分句首**算起跳，程度副词只在**紧接情绪形容词**时
> 算直述。加新词往词族里加（`SUDDEN_ADVERBS` / `INTENSIFIER_ADVERBS` / `FLAT_EMOTION_ADJS`），
> 别新开一条只禁一个词的规则。
>
> **豁免范围**：只扫引号外叙述层（台词里的「你非常生气」是人物口语）；量词「只剩十分钟」
> 「十分之一」、否定式「不太高兴」、非情绪搭配「非常时期」「极其重要」都不在判据位置内。
>
> **破折号为什么降级（v3.0）**：旧版一律 blocking，实测 137 字标准对话段 4 处全判死——
> 其中 3 处在引号内。中文里表示「话说一半被打断」只有破折号一种写法，改了读者分不清
> 谁打断谁。而且合并口径的实测本身不成立：拆开后不同模型方向相反（一个是 δ −0.54，
> 比人类还少；一个是 +0.95，偏多），合并统计把相反方向抵消成了「不显著」。
> 现在：引号内一律 advisory；引号外保留 blocking，但要在密度警戒线以上。
> 详见 `rejected-signals.md` X-10。

## 三、按处置方式分四类（advisory 20 条 + 条件降级的破折号）

`severity` 说「拦不拦」，`category` 说「**该不该改**」。这一层是 v3.0 新加的，因为把三类
完全不同的东西塞进同一个 advisory，模型无从判断：

| 分类 | 是什么 | 默认动作 | 条数 |
|---|---|---|---|
| `ai-tone` | 真 AI 腔：句式模板、推理方式、程度加码 | **改**，不改就是机器腔 | 13 |
| `cliche` | 网文水词：眼中闪过、深吸一口气、全场哗然 | **可删可留**，删了只是不那么水 | 4 |
| `literary` | 文学手法：比喻、引号强调、过滤动词 | **多数保留**，先判断功能 | 3 |
| `readability` | 可读性：碎句号、段落呼吸、连接密度、破折号、短对话堆砌 | **看节奏**，不是 AI 指纹 | 9 |

### ai-tone（13 条：7 条 blocking + 6 条 advisory）

| 类型 | 触发 | 改法 |
|---|---|---|
| `hard-banned-word` / `not-is-comparison` / `reverse-not-is` / `voice-contrast` / `negation-parade` / `trailer-ending` / `trailer-summary` | 见上节 | 见上节（全部 blocking） |
| `negation-pair-tic` | 「没A，也没B」≥3 处 | 改成他做了什么，只留真要强调的一两处 |
| `emotion-label-tic` | 「感到/心头＋情绪词」「一阵＋情绪＋涌上」≥4 处 | 逐处删除测试，换该角色特有的行为（避开攥拳/咬唇等通用手势） |
| `abstract-summary-tic` | 命运/棋局/这一刻终于明白 ≥3 处且 ≥4/千字 | 回到角色当下可见的文件、动作、物理后果 |
| `reasoning-chain-tic` | 知道/明白/必须/需要 ≥8 处、≥2 个桶、≥18/千字 | 把判断落到动作、物件、对话、现场反馈 |
| `formulaic-parallelism` | 跨段「不是…/也不是…/只是…」工整否定铺排 | 若只是复述细纲或拖慢画面，压成一次判断 |
| `intensifier-abuse` | 叙述里 非常/极其/无比/十分/特别/格外/相当/极度 ≥4 处 | 删九成，程度靠具体画面给（「三天没合眼」代替「非常大的压力」） |

> **`reasoning-chain-tic` 的 connector 组已收窄（v3.0）**：「这意味着/也就是说/换句话说」
> 三项移出——配对复测三项全反（人类 0.027 vs AI 0.016/千字），小说里「也就是说」多半是
> 角色口语转述。留下的才是真 AI 腔：真正的问题在于 / 问题在于 / 关键在于 / 在这种情况下 /
> 按照这个逻辑 / 只有这样 / 想到这里。见 `rejected-signals.md` X-2。

### cliche（4 条，网文水词 —— 该删但不该焦虑）

| 类型 | 触发 | 改法 |
|---|---|---|
| `cliche-density-tic` | 高危套词 ≥8 处且 ≥12/千字 | **不要同义词轮换**，改成具体动作/物件/后果 |
| `stock-reaction-tic` | 指尖/指节/喉结/眼圈/声音放轻等通用反应 ≥4 处且 ≥1.5/千字 | **逐处删除测试**：只标注情绪、不改变选择/关系/物件/动作结果的删掉，不要换部位或同义动作 |
| `micro-action-tic` | 「了下/了一下」式轻量补语 ≥5 处且 ≥6/千字 | 合并动作 beat，换具体细节 |
| `crowd-sync-tic` | 强同步词（全场哗然/鸦雀无声/齐刷刷/无人敢）单次即报；泛指词（所有人/众人/全都/人群）≥4 处 | 拆成 ≥3 种立场（领头/跟风/尴尬/回避/私语/走神），或指明某一个人做了某个多余动作。详见 `human-reaction.md` |

> 这一类的共同点：**人类也这么写，只是写得更省**。所以处理方式是「删到不腻」，
> 不是「一条都不许有」——后者会把文字修成没有质地的干净样板。

### literary（3 条，文学手法 —— 多数该保留）

| 类型 | 触发 | 改法 |
|---|---|---|
| `metaphor-density-tic` | **同一段里**比喻标记 ≥3 个（不是全章密度） | 留最有叙事功能的那个，其余回到具体动作、物件、声音或后果；**不要换新比喻** |
| `quote-emphasis-tic` | 叙述层 1–4 字引号强调 ≥3 处 | 只留反讽/转述必要的，其余去引号 |
| `filter-verb-tic` | 一段内 ≥3 **种**不同过滤器动词（看见/听见/感到/觉得/注意到/发现/意识到…）；或整章 ≥6/千字 | 删掉感知动词，把被感知的东西直接摆出来。详见 `narrative-distance.md` |

> **`metaphor-density-tic` 改判据（v3.0）**：旧版按全章密度（≥7 处且 ≥3/千字）判，
> 而配对复测显示**人类比喻标记是 AI 的 2.4 倍**（0.38 vs 0.16/千字）——按密度判等于
> 惩罚爱用比喻的作者。真正的 AI 味不是「一章里有几个比喻」，是「一段里连着比三下」。
> 现在逐段判，也顺带给出可定位的行号。见 `rejected-signals.md` X-7。
>
> `filter-verb-tic` 按**不同种**计数，同一动词连排是排比，不算——旧版按个数计数，
> 把「他看了一眼，看了一眼，又看了一眼」误判成过滤器动词堆叠。

### readability（9 条，节奏与标点 —— 不是 AI 指纹）

| 类型 | 触发 | 改法 |
|---|---|---|
| `em-dash` | 引号内破折号恒 advisory；引号外且 <2/千字 也 advisory | 只收「连叙述带台词全靠破折号串场」，不删单个破折号 |
| `period-stutter` | 连续 6 个 ≤5 字短叙述句 | 合并成中长句，补回画面与连接 |
| `weak-verb-tic` | 「进行/作出/加以/予以＋抽象名词」≥2 处（只扫叙述） | 还原硬动词；详见 `chinese-prose-craft.md` 第二节 |
| `action-list-tic` | 同段连续动作动词 ≥5 个＋≥4 个分隔符 | 合并琐碎步骤；打斗编排可保留，必要时用犹豫/误判/环境反馈做缓冲 |
| `system-notice-formality-tic` | 方括号规则行 ≥4 行且硬规则词密集 | 保留为载体（屏幕/公告），只在载体内部白话化，不改成叙述者解释 |
| `overcompressed-prose-tic` | 叙述段 ≥45 个且 ≤15 字段占 58%＋、自然连接偏少 | **禁止机械注水**，先通读判断是否真有提纲感 |
| `low-connective-density-tic` | 功能词 <100/千字且长承接句 <8% | 补必要连接和中长句群 |
| `decorative-symbol` | 正文出现 ✦✧✨❖◆◇▪★➤ 一类符号点缀或分隔 | 去掉符号，分隔场景用空行 |
| `short-dialogue-run` | 连续 4 段纯台词短段（引号内可见字符 ≤22），中间无动作/神态/场景 | 对白来回要插一个动作或环境细节；论坛/短信/弹幕/围观喊话/念信属合理写法，可留 |

> 这一类全部是**读感指标，不是作者指纹**。同一条命中，在快节奏打斗里正确、在铺陈段里
> 是毛病。判断依据永远是「这一段该快还是该慢」，不是「lint 说超了」。

## 四、X 级：已否决，照常计数但**不改**

有一类特征，命中的是**人类写作的常态**——第一轮不配对对照里看着像 AI 味，
同题同事实配对复测后人类用得比 AI 还多，或者根本没差异。

它们不进 finding、不拦门禁，但结论记在 `references/rejected-signals.md`（X-1 ~ X-10），
并由 `scripts/test-rejected-signals.py` 机械守卫：**谁把它们加回规则表，测试就红。**

已知的十条（详见该文件）：

序号词小标题 · 「这意味着/也就是说/换句话说」· 空转句引列表 · 概括替代 · 精确数字堆砌 ·
漂亮词黑名单 · 比喻密集 · 句长必须参差 · 「其」字用量 · 破折号多

> 记住这一档的存在意义：**lint 只有「拦」和「提示」两级时，规则库只会增不会减**。
> 每次有人觉得「这个像 AI」就加一条，三年后没人说得清哪条还有效。

## 五、白名单豁免

在书目录下建 `.deslop-whitelist`，每行一个字面量片段，扫描时整段排除：

```
<!-- 去味:跳过 -->
职业名称（如"律师"）
专有名词
固定搭配
```

只豁免**本书确实需要保留**的字面片段。不要把整个句子塞进去——那是绕过门禁不是解决问题。

## 六、模型退化检测

AI 写到中段会退化且自己意识不到，`check-degeneration.js` 专查这类：

```bash
node scripts/check-degeneration.js --fail-on=blocking 正文/第001章.md
```

| 类型 | 含义 |
|---|---|
| 复读/打转 | 长句重复、连续相同行 |
| 截断 | 文件末尾无终止标点 |
| 占位/拒绝语 | 作为AI / 我无法继续 / 此处省略 / 乱码 |
| 工程词泄漏 | 细纲 / 情节点 / 本章 / 下一章漏进正文 |

blocking 命中后的正确反应：**重新生成该章**，把 finding 作为约束喂回去，限制重试次数，然后带着证据交给用户判断。**不要手工逐条修补**——退化是整体性的，逐条改会留下缝。

> 该脚本刻意保守：网文常用的排比/复沓/弹幕刷屏/重复台词是正常节奏，短句与台词重复已豁免。

## 七、标点归一

```bash
node scripts/normalize-punctuation.js 正文/*.md
```

统一全半角与中文标点。**去味前先跑标点归一**，否则 lint 报的位置会因为引号/破折号混用而漂移。

## 八、操作顺序

```
1. node normalize-punctuation.js    先归一标点
2. node check-degeneration.js       查退化（若有 blocking，先重生成）
3. node check-ai-patterns.js --json > before.json   留一份改前基线
4. 清 blocking（8 条，机械改写；破折号先看引号内外与密度）
5. 逐条判断 advisory（20 条）——先看 category：ai-tone 该改，cliche 可删可留，
   literary 多数保留，readability 看这一段该快还是该慢
6. node check-ai-patterns.js --diff=before.json     看改完是修好了还是改过头了
7. 重跑直到 blocking = 0
8. forge.py gate --stage all        完整门禁（draft + final 两层；换平台加 --platform）
```

## 九、AI 合规

平台打击「AI 直出」，但**不禁止 AI 辅助**。

- 不要把 AI 一次性生成的正文直接标称为可发布内容
- 每章必须经过：blocking 清零 + advisory 人工判断 + 至少一遍自己的语感通读
- 机器规则只能去掉机械感，**不能替你写出好句子**
