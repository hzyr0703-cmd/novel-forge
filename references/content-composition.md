# 内容构成判据（读者为什么追，而不是文字像不像人）

> 本文件补的是 skill 长期缺的一层：**内容构成**。
> 句子层（AI 词、句式、段长）和形状层（分布、多样性）全绿，仍然会掉追更——
> 因为读者追的不是"文笔干净"，是"这一章发生了什么、值不值得明天再来"。
> 实测来源：《开局无异能》102 章（2026-11-15 体检 + 同类对比），见项目 `全书流水线体检-2026-11-15.md`、`同类对比-内容差距-2026-11-15.md`。
> 与 P30 的关系：下面每个数字都是**细纲阶段的门禁靶**，不是写作时的配额。写正文时只看诊断问句。

## 一、三条读者侧判据（细纲必须回答，答不出就返工）

这三条是"做了但读者没感觉"的根因。三条全中的书，读者会在第 40–60 章开始默默退出。

### R1 公开验证：爽点必须被人看见、被人报价

**判据问句**：这次赢，除了主角自己，还有谁在场？散场后有没有人因此改变对他的出价/态度/称呼？
若答案是"没人看见"或"看见了但没人反应"——这条爽点只对主角成立，不对读者成立。

- 反例形态：私下试出新能力 → 只在内心确认"我变强了"；赢了一局但围观者被淡化处理（书里第 2/3/55/66 章的围观全被调低）。
- 正确形态：当众出手 + 第三方报价/议价/评级变动 + 可被下一次引用的公开记录（榜单、通缉、委托价、别人的原话）。
- 细纲字段：`public_validation: {audience: ...; witness_change: ...}`。
- 频率底线：**每卷至少 2 次**"公开定价"事件；相邻两次间隔 ≤ 25 章。

### R2 反派败绩：有名有姓的对手必须真的输过一次

**判据问句**：到目前为止，有名字的对手里，谁被主角当面打输过？不是谈判、不是威慑、不是"以后再说"。
若答案是"零"，说明全书对抗只有施加压力，没有释放压力——读者攒了 50 章的憋屈没有出口。

- 反例形态：反派只在谈判桌上出现、威胁后离开、"塔"只闻其名（书里 102 章有名反派败绩 = 0）。
- 正确形态：一次**被记录下来的败**——受伤、撤退、失约、被当众拆穿，且主角付出可见代价。
- 细纲字段：`antagonist_defeat: {who: ...; form: ...; cost: ...}`。
- 频率底线：**每卷至少 1 次**；单次失败必须能被下一卷的反派引用（"上次是你运气好"）。

### R3 成长可见：等级/能力变化必须落在读者能数的地方

**判据问句**：这一卷里，主角的可量化指标（等级、额度、权限、名次、资产）动过几次？读者能不能说出"上次是多少、这次是多少"？
冻结超过一卷的成长线等于没有成长线，读者会当成设定而不再是期待。

- 反例形态：Lv.1→2（第 21 章）→3（第 37 章）后冻结 65 章；两次质变全在私下完成。
- 正确形态：升级/破限发生在有见证的场合，且当场产生一个**可换算**的结果（报价、权限、欠债、名次）。
- 细纲字段：`growth_marker: {metric: ...; from: ...; to: ...; witness: ...}`。
- 频率底线：**每 15 章至少 1 次**可数变化；同一指标连续 3 章不变且无铺垫 → 报 advisory。

> 三条判据与下面的构成规则的区别：判据管"这一卷有没有那件事"，规则管"这一章是不是纸面章"。
> 先过判据（卷级），再过规则（章级）。

## 二、五条内容构成规则（细纲阶段门禁）

来源：项目 `大改方案-2026-11-16.md` 第五节 + `全书流水线体检`。此前只写在日更 cron 里，
现在进 skill，`forge.py gate --stage outline` 默认检查。

### C1 纸面内容占比（blocking）

单章里"纸面/算账/清点/读文件"类段落 ≤ 25%（按段计）。
纸面词族：账面、台账、记录、登记、清单、报表、对账、核算、条目、备注、文件、档案、条款、目录、截图、价目。

- 为什么：卷三纸面词密度 4.37/千字（卷一 0.98），是读者流失的直接信号；纸面段落没有动作，只有信息。
- 豁免：主角独自读文件但**同时发生一件事**（有人在门外等、有倒计时、有身体代价）不算纸面段。
- 机检：`check-content-composition.py` 按段统计纸面词族命中率。

### C2 数字问答（blocking）

单章"一问一答报数字"至多 1 处（"多少？""三十七万。"）。连续两处以上 = 记账流水。

### C3 连续谈话章（blocking）

禁止连续 2 章以"谈话/读文件/开会"为主要场景（占比 ≥ 50% 即算）。
对话多不等于谈话多——区别在有外部事件推进。

### C4 滚动实战（advisory）

滚动 5 章内至少 1 章含实战：战斗、副本、委托处置，且"接单—处置—结算"齐全（只写结算不算）。

### C5 独处章限频（advisory）

独处实验/清点/对文件为主场景的章，滚动 10 章至多 1 章。

> 为什么 C4/C5 是 advisory：它们判定要跨章回看，写单章时无法自证；且强行凑实战会让节奏更假（P30）。
> C1–C3 是单章可判的，能当场改，所以进 blocking。

## 三、写作时的诊断问句（不设配额）

写这一章之前问三句，能答上再动笔：

1. **这一章结束，读者的处境比开头好还是更糟？**（都不变＝水章）
2. **有人会知道这件事吗？**（没人知道＝私下爽点，写也白写）
3. **删掉这一章，后面哪一章会觉得少了东西？**（答不出＝可以并章）

写完再问三句（对应 C1–C3）：

1. 这一章有几段是在"看纸/算账/念数字"？
2. 有几次是一问一答报数字？
3. 上一章是不是也是谈话/读文件章？

## 四、细纲写法（每章必填的四个字段）

细纲文件 `细纲/第N章.md` 顶部加一段 YAML-ish 头（`spec_check.py`/`check-content-composition.py` 都会读）：

```yaml
scenario: 战斗 | 副本 | 委托处置 | 谈话 | 纸面 | 独处实验 | 日常过渡
public_validation: "围观者：安济巡夜队；态度变化：从雇到抢"
antagonist_defeat: ""        # 本卷暂无则留空
growth_marker: "额度 4.2万 → 9.8万（当众结算）"
event_count: 2              # 本章真实发生的事件数（不含信息交代）
```

- `scenario` 必填，且必须与正文实际形态一致（对不上按"细纲未兑现"报）。
- `event_count` = 0 的章，细纲阶段直接拦（这是"什么都没发生"的机器信号）。
- 三条判据字段按卷填：卷纲里每卷末尾汇总一次 `R1/R2/R3` 是否达成，未达成的下一卷补。

## 五、卷级检查（卷纲提交前）

每卷收官，在卷纲末尾追加一段：

```yaml
volume_check:
  public_validation: 2      # 本卷公开定价次数（需 ≥2）
  antagonist_defeat: 1      # 本卷有名反派真败次数（需 ≥1）
  growth_steps: 3           # 本卷可数成长变化次数（需 ≥ 章数/15）
  longest_no_event_run: 2   # 连续无事件章最长长度（需 ≤3）
```

任一项不达标：不要下一卷先写，先补这一卷的缺口（补在已有章之间，或下一卷开头 3 章内偿还）。

## 六、与门禁脚本的接线

```bash
# 细纲阶段（新增，默认纳入 gate --stage outline）
python3 $S/check-content-composition.py --book <书目录> --chapter N
python3 $S/check-content-composition.py --book <书目录> --audit   # 存量迁移体检：缺哪些字段（只报告，退出码 0）
python3 $S/forge.py gate --book <书目录> --chapter N --stage outline

# 单章正文写完后的构成自查（advisory 汇总，不阻断）
python3 $S/check-content-composition.py --book <书目录> --chapter N --layer draft
```

退出码语义与 `spec_check.py` 一致：C1–C3 命中即非 0；C4/C5 与三条判据只打印清单。
判据在卷级用 `--volume` 汇总（读卷纲 `volume_check`），缺字段报"未填"而不是"未达标"。

## 七、存量书迁移（2026-11-17 实测）

老项目第一次接这套门禁，按三步走，**不要指望关键词自动判定**。

1. **体检**：`--audit` 只报「哪些章缺 scenario / event_count」，不判内容。
2. **人工判读**：逐章看细纲的「章节目标」首句 + 章节标题，给一行标签。实测 103 章约 40 分钟；
   关键词打分脚本在 9 章对照上只对 4 章（把「听证」判成纸面、「对账」判成谈话），不可用。
   判读口径：这一章**读者跟着看了什么**——看人说话→谈话，看账/文件/清点→纸面，看打/救人/接单验收→委托处置，
   看进场打捞通关→副本，看主角一个人试→独处实验，什么都没有→日常过渡。
   标签写进细纲 yaml 头，`scenario_source: manual-review` + 一行理由，便于日后复核。
3. **卷级快照**：给每卷 `volume_check` 填**现状值**（不是目标值），让门禁把历史缺口显形。

实测结果（某 103 章书）：24 章被 C3 拦下，集中在卷三；卷三 `antagonist_defeat: 0` 触发 R2 阻断。
这不是脚本误报——那本书的读者反馈就是「流水线感严重」，两处结论对得上。

判读顺序建议：先判 C3 相邻对（只需知道每章属于哪类），再判 C4/C5 窗口（最近 5 章、10 章），最后补卷级四字段。
不要为了过门禁改标签——标签错了，门禁就白装。
