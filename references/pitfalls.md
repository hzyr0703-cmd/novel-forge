# 实操坑位（P1–P32）

> 定位：本文件是 **v3.1 从 SKILL.md 第十四节迁出的坑位台账**，记「为什么规则是现在这个形状」。
> 它不是写作技法，是**改规则 / 改脚本 / 排查异常 / 怀疑自己写歪了**时的对照表。
>
> 什么时候读：
> - 要动 `check-ai-patterns.js` 的规则表、`spec_check.py` 的 `THRESHOLDS`、`tracking_commit.py` 的 schema → **必读全文**
> - 门禁报了看不懂的红、或某个判据的结果与你直觉相反 → 按编号查对应条
> - 想「这条规则是不是太严 / 太松」→ 先看 P18（门禁越严正文越像 AI）、P28（禁词不禁族）、P30（配额诱导凑数）、P32（常驻层规则平权）
>
> 编号 P1–P32 是稳定标识，外部引用（脚本注释、CHANGELOG、其他 references）按编号指过来，**只增不改号**。

## 一、落盘与追踪（P1–P10）

1. **声明块不进正文（v2.0 起）**：`check-degeneration.js` 会把出现在文件最末尾的 `<!-- ... -->` 型 HTML 注释判为 truncated（blocking）。**v2.0 起声明块（含钩子型号）一律写 `meta/第N章.json`，不写正文**；仅当手写正文里临时保留了注释时才适用「注释放在最后一段正文之后但不做文件最后一行」这条。

2. **声明块的冒号用全角`：`**：仅适用于正文里残留的 HTML 注释声明（v2.0 起改为 meta/ JSON，正常不再出现）。JSON 里用标准 ASCII 冒号。

3. **tracking_commit 快照精确匹配**：transaction 的 `character_snapshots` 必须与 `delta.character_changes` 里的 core 角色**一一对应**——多带未变更角色的快照会报错，漏带已变更角色的快照也会报错。

4. **修订 delta 是完整记录**：revision 模式下 delta 会整份替换该章记录，只写改动项会静默清掉原有的角色变化/伏笔变化（脚本会 WARNING）。重写流程见 `plot-recovery.md` 第三节。

5. **「部分揭示」语义**：`forge.py truth` 拦截「未揭示却出现在读者已知表」。凡读者在正文里亲眼看到过的谜团（哪怕只看到谜面），登记为「部分揭示」+ 揭示章；完全没露过面的真相才能标「未揭示」。

6. **长篇章数口径**：规划卷章数时先定每章字数（如 2300）再算章数（25 万字≈110 章），不要凭感觉写「每卷 25 章」。

7. **normalize-punctuation 会改写省略号/引号**：对正文做字符串替换后，以最新文件内容为准再做精确匹配编辑。

8. **爽点声明按就近生效计算**：显式爽点标记视为「描述它前面刚写完的那一段」，所以声明集中写在文末也能正确归属，不必塞进正文中间。

9. **模板是严格白名单**：`tracking_commit.py init` 的 JSON 多一个键就报错，`_说明` 这类注释键也不行。字段说明看 `templates/README.md`。

10. **别找不存在的脚本**：早期版本的报错信息指向过 `forge.py plan` 和 `storyctl.py`，两者都不属于本技能，已全部改为指向实际存在的命令。

## 二、检测算法（P11–P17）

11. **按段落切分，别按句子**：跨章复述检测最初按句子切分再合并到目标长度，结果「原创段 + 复述段」混进同一指纹，9 个自然段被压成 2 段，注入的复述完全漏检。段是作者写下的完整语块，跨段混合会直接摧毁段级检测的前提。详见 `crossrepeat.md` 第二节。

12. **测试脚本别用 `os.system` 跑中文路径**：`os.system` 会把参数经 `cmd.exe` 传，中文目录名变成「文件名、目录名或卷标语法不正确」，子进程根本没执行，测试却显示「未检出」——静默通过比失败危险。用 `subprocess.run([...])` 传 argv 列表。

13. **测试数据必须走正规 schema**：事实冲突检测第一版按猜想的 schema 编写，5 条死亡规则依赖台账白名单里不存在的字段，手搓测试数据绕过了 schema 校验，9/9 全绿是假绿。测试数据要么经 `tracking_commit.py` 正规写入，要么对照 `normalize_snapshot` 白名单逐字段构造。修复时已把 `died_in`/`revived_in` 正式加入快照白名单（可选字段，旧台账不受影响）。

14. **MinHash 别用 XOR salt 捷径**：`md5(s) XOR salt_i` 看着像哈希族，实际 XOR 双射≠min-wise independent，各 permutation 强相关，估计有系统偏差。用 Carter-Wegman 2-universal 族（`(h1 + i·h2) mod 2^64`）。同理，salt 派生放 shingle 循环外，否则 O(shingles×64) 次 sha256。

15. **段数门槛会漏掉整段逐字复制**：跨章复述的 `min_flagged_segments=2` 拦「轻度呼应」，但一整段 0.89 相似度的逐字搬运也被它拦了。已加 `single_segment_jaccard=0.8` 出口：单段几乎逐字照样报。改这类阈值时想清楚它防的是什么、会误放什么。

16. **论述文规则直接套网文会集体失灵**：lieflat 的结构同款检测用 10 字句长阈值——网文「山风从谷底涌上来」9 字短句全被滤掉，检测归零。翻案腔正则 `[^，。]` 不容逗号——网文口语化「与其说…，不如说…」全漏。移植任何语料驱动的规则，先拿目标文体的真实文本验证触发，再信它的数据。

17. **正则要先对上游例句自测**：拟人化喻体的上游例句「像一位智慧的导师」是**前修饰**，初版正则只写了后修饰形态，照抄上游数据却漏检上游自己的例句。移植正则后第一件事：拿来源文档的原始例句跑一遍。

## 三、判据方向（P18–P31）

18. **blocking 别贪多（v2.0 核心教训）**：旧版把对话占比/爽点/感官/回报/温度全当 blocking，模型为了过门禁开始「填格子」——每章硬塞感官、硬凑爽点，正文反而越来越像机器。v2.0 只留四项 blocking（字数/段长/AI味/章末钩子），其余降 advisory。**门禁越严，正文越像 AI**——这条反直觉但实测成立。**注意「四项」只数规格层**：规格层的「AI 味」就是 lint 8 类的汇总入口，去重后 gate 合计 12 类（规格自有 3 项 + lint 8 类 + 平台合规 1 类；旧「13 条」系重复计数，本地修订 2026-11-06 已纠正，见 `gates-and-spec.md` 第三节 blocking 清单）。

19. **分布检测看的是「像不像人」，不是「对不对」**：`check-distribution.py` 的句长标准差/偏度对比人类基线（`human-baseline.json`），判的是「这个分布人类写不写得出来」。基线不是手填的——**由 `scripts/collect-baseline.py` 从本地人类语料采集生成**，跑 `python scripts/collect-baseline.py --show references/human-baseline.json` 可核查来源、书数、章数与采集口径。它是**人工审稿的前置线索**，不是违规判定——所有输出都 advisory，不阻断。

20. **对话窗口方差要够窗口数才判**：`check-distribution.py` 的对话波动检测最初 ≥3 窗就判，2000 字的章只有 3–4 窗，噪声大，人类作品频繁误报。改成 ≥5 窗才判，误报消失。**小样本上的方差没有意义**。

21. **导出层宁可不导，不可带脏**：`export.py` 先清洗再校验——HTML 注释、`[DRAFT]`、skill/脚本名、路径全剥掉，剥完还残留 `agent_created`/`forge`/`tracking` 就退出非 0。平台看到的就是导出文件，一处残留可能就是一次判 AI。

22. **裸声明行会漏**：声明块正常包在 `<!-- -->` 里会被剥离，但作者手写时偶有裸的「温度：冷」独立成行——`export.py` 单独用正则抓这种「短行+键+冒号+短值」的形态，避免误伤正文里正常的冒号句。

23. **advisory 要靠「写完自查」落地（v2.1.1）**：v2.0 把非功能对话、段长波动、句长波动降为 advisory 后，模型优先满足 blocking，advisory 容易被跳过——《燃识》四章实测，闲笔进了叙述层，对话层仍全是功能句。解法不是升回 blocking（那会回到「填格子」），而是 SKILL.md 写章序列 5.5 步的显式自查点：机器不拦，写完必须自己过一遍。

24. **段长分布是 AI 指纹的重灾区**：四章《燃识》实测，闲笔、环境细节都加了，但段长全部在 30 字以内，从不接近人类基线 p90（66.5 字）。短段不是错，**永远短段**才是 AI 腔——人类会在铺陈、闪回、过渡时写长段。check-distribution.py 已加长句/长段存在性检测（1b/2b）补这个盲区；写作侧解法见 `writing-craft.md` 正向约束第 7 条。

25. **分布不达标要走回改手册，不是重写**：句长 sd<13、整章一个长句都没有的已提交章，按 `style-refit.md` 四类动作逐章回改（删复述→黏合→修硬伤→补质感），验收线 sd≥13 / 长句存在且句式不重复 / p50 不动 / 对话率不降 / blocking 0。《燃识》36–41 五章实测全部一轮通过。**别拿「≥10%」当验收线**——配额会诱导凑数（见 P30）。

26. **顶字数上限的章先删再加**：改前字数距 3200 不足 100 字时先删复述腾余量再补质感，否则必爆字数 blocking 返工（ch36 实测 3147→3272）。

27. **黏合段受 90 字段长上限约束 + 删段留连续空行**：长句可以长但段落超 90 字是 blocking，黏合完逐段看长度按句拆回；每章收尾把 `\n{3,}` 压成单空行，否则导出层比对出幽灵差异。

28. **禁词不禁族＝在教模型背替换表（v2.8）**：旧版只禁「忽然」不禁「突然」、只禁「非常」不禁「特别」，两句语义、节奏、画面完全相同，门禁把 a 判死、把 b 判活。实测代价：模型学到的不是「用动作 beat 起跳」，而是「忽然→突然」的映射表——门禁在奖励更假的文字。修法是判**位置 + 词族**：突变副词只在段首/分句首拦（句中「他忽然想起」放行），程度副词只在紧接情绪形容词时拦（「非常时期」「十分之一」「不太高兴」放行）。加新词往词族里加，绝不新开一条只禁一个词的规则。

29. **同一现象三套口径＝三套事实（v2.8）**：段长曾同时是「文档 70–100」「lint >200 advisory」「spec 90 blocking」，91–100 字＝文档说可以、机器判死；字数、规则数（22/26/29）、版本号（frontmatter/CHANGELOG/git）同样漂移。根因是「约束写在文档、判据写在脚本、两边各改各的」。修法只有一条：**每个数字只留一个事实源**——段长与字数去看 `spec_check.THRESHOLDS`，规则数跑 `check-ai-patterns.js --list-review-classes`，版本号三处同步 bump。文档改数字时先跑脚本对一遍，不要凭记忆写。

30. **写成配额的目标，模型会凑数（v3.0）**：「句长要有波动」写成「40 字以上长句 ≥10%」，模型就会去合并句子凑到 10%——句子变长了，节奏反而更假。这不是模型不听话，是**指标一旦可数，就变成优化目标**。人机句长离散度实测无差异（`rejected-signals.md` X-8），说明这个百分比本来就不该当目标。改法：把 KPI 改回**诊断问句**——「整章一个长句都没有？」「铺陈处是不是被拆碎了？」。同类风险：段长分布、对话占比、爽点间隔，凡写成「≥N%」或「每章 N 个」的，都要问一句「模型会不会为了达标造假象」。

31. **合并口径会把两个相反的真信号抵消成假阴性（v3.0）**：破折号「合并统计不显著」，拆开是两个方向——一个模型比人类还少（δ −0.54），一个偏多（+0.95）。合并后平均成零，于是「破折号不是 AI 味」和「破折号是 AI 味」两边都能拿这份数据支持自己。同理，`check-distribution.py` 拿 4 本书的 `merged` 当基线，若两本书在某指标上方向相反，平均给出的「正常」就是假的。现在它会打印**组间极差**（`[组间]` 行），极差 ≥5× 的指标额外提示「人类内部不一致，别单独当判据」。**做统计先问：这个平均是谁和谁平均？**

32. **常驻层的规则会平权，长下来的文档会把「写作」变成「核对清单」（v4.6）**：SKILL.md 每次加载都进上下文，里面的每一条——不管轻重——拿到的注意力是均等的。v4.5.1 那份 30,339 字符、701 行的常驻层里塞了 69 处强制型指令（必须/禁止/不许/不得/一律/强制）和 9 处数字配额，模型写一章时的实际动作就退化成「逐条对照 → 凑够 → 交付」，而不是先想这一章要让读者看到什么。证据不是感觉，是同一本书的实测：卷二章长 1854±44 字（CV 2.4%，正好贴着「1800–3200」的带内均值）、章中钩子声明 0.5 占 68/102 章（正好落在「40%–60%」中间）、三重回报「信息+情绪+进展」占 86%（正好贴着「≥1/3」——它只会用最省事的那一组）。**规则一旦写进常驻层并带上数字，就一定被执行成模板。** 改法见 v4.6.0：常驻层只留判据与路由（约 1.1 万字符、16 处强制词、0 处配额），细则下沉 `references/` 按需加载，数字唯一事实源交给 `spec_check.THRESHOLDS`；配额一律改问句（P30）。**再想往 SKILL.md 里加「每章至少 N 个…」时，先读这一条。**

## 四、改完跑什么（回归矩阵）

改任何脚本后跑 `python scripts/forge.py selftest`（改动前先看它是否全绿）。

| 你改了什么 | 必须额外跑 | 为什么 |
| -- | -- | -- |
| 台账字段（`_pick` / `_as_text` 那几处别名） | `test_schema_compat.py` | 交叉验证两种 schema 结果一致 |
| `llm_review.py` | `test_llm_review_pairing.py`（离线逻辑）+ `test_llm_review_e2e.py`（真实 HTTP 路径） | 换位投票与 JSON 提取的鲁棒性不能靠肉眼 |
| `ledger.py` / factconflicts 的伏笔规则 | `test_ledger.py` | 挂账与回收时序 |
| `recall.py` / 台账 `aliases` / `追踪/aliases.json` 解析 | `test_recall_alias.py` | 核心是那个对照：`--no-alias` 必须退回零命中，否则测的不是别名 |
| lint 规则（加词、改阈值、调 severity） | `test-rejected-signals.py` | 它拦「把已否决特征加回规则表」，并核对 category 漏登记 |
| 任何文档 / 阈值 / 规则 | `check-doc-consistency.py` | 把「文档里的数字」与「代码里的事实」逐项对账（规则数/段长/字数带/平台预设/版本号/deslop 覆盖），不一致退非 0 |

这个矩阵存在的理由就是 P29：数字散落在十几个文件里，靠人记必然漂移。

第三方来源与修改约定见 `scripts/VENDOR-NOTICE.md`——**不要静默调整 lint 阈值**，每个数字都对应一条语料校准记录；规格阈值与分层改 `spec_check.py` 的 `THRESHOLDS`，换平台见 `platform-adaptation.md`，分布基线见 `human-baseline.json`。
