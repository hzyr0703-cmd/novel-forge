# 对标书语义层拆解流程（剧情模块库）

> 定位：`scripts/analyze_book.py` 负责机器能算的（文风分布/标点指纹/
> 高频用词），本文件负责**模型执行的语义层**——把一本对标书拆成
> 可复用、可检索、可对照的剧情模块库。这是 SKILL description 里
> 「拆解对标书建立剧情模块库」的执行流程。
>
> 版权纪律：拆解产物只写**结构与规律**（身份/动机/节奏/机制），
> 不复制原文句子进模块库。引用原文作锚点时单条不超过一行，
> 且标注章节号。拆文库是给你的参考，不是洗稿的原料。

## 触发方式

- 指令：「拆这本书」「把 XX 建成对标库」+ 对标书路径/目录。
- 脚本先跑：`python scripts/analyze_book.py --book <对标书目录> --project <书目录>`
  ——产出 `对标/<书名>/` 的统计底座，语义层在这个目录里继续。

## 产出结构（与脚本产物同目录）

```
对标/{书名}/
├── 文风基线.json      ← 脚本产出，check-distribution --baseline 消费
├── 文风.md            ← 脚本产出
├── 拆文报告.md        ← 脚本产出（内含语义层待办清单，逐项打 ×）
├── 概要.md            ← 待办 1
├── 角色/              ← 待办 2（每核心角色一个文件）
├── 剧情/故事线.md     ← 待办 3
├── 设定/世界观.md     ← 待办 4（可按主题拆多文件）
├── 金手指.md          ← 待办 5
└── 爽点抽样.md        ← 待办 6+7（爽点密度 + 节奏样本）
```

## 七个待办的做法

### 1. 概要.md

- 全书一句话梗概（谁+在哪+靠什么+对抗谁）。
- 你读到/拆到哪一章（断点），后续补拆从这里继续。
- 全书结构定性：几卷、每卷一个动词（立/破/收）。

### 2. 角色/（每核心角色一个 md 文件）

每个文件固定五段，单文件 ≤ 60 行：

| 段 | 内容 | 判据 |
|---|---|---|
| 身份 | 出场身份 + 实际身份（如有双层） | 两层都要写，反差是爽点原料 |
| 语言指纹 | 口癖、句长习惯、称呼方式 | 写对话时直接仿这个指纹 |
| 动机链 | 想要什么 → 为什么 → 代价是什么 | 动机链断的角色必然工具人化 |
| 关系 | 与主角及其他核心角色的张力轴 | 一句话一条，写轴不写事件 |
| 状态 | 拆解断点时的处境 | 供续拆对齐 |

### 3. 剧情/故事线.md

- 主线 1 条 + 支线 N 条，每条一行：`线名 ｜ 起点（章）｜ 当前位置（章）｜ 悬置点`。
- **悬置点**是拆解核心：对标书靠什么吊着读者——每条线写清它
  当前欠读者什么、预计在哪类事件里还。

### 4. 设定/世界观.md

- 按主题拆（力量体系/地理/势力/规则），每主题 ≤ 40 行。
- 只写**对剧情起作用的规则**——写了但从未影响剧情的设定不进库。

### 5. 金手指.md（对标书的爽点发动机）

固定四问：

1. 能力边界：能做什么/不能做什么（边界越具体越可抄结构）。
2. 成长成本：升级要付出什么（无成本金手指是它的弱点，是你的差异空间）。
3. 升级路径：从获得到毕业分几阶段，每阶段解锁什么。
4. 爽点公式：这个金手指产生爽点的固定句式是什么
   （例：「别人要苦修十年的东西，他看一眼就会」）。

### 6. 爽点抽样（最近 10 章）

表格三列：章号 ｜ 爽点类型（打脸/扬名/得宝/升级/情感/解谜/复仇）
｜ 间隔（距上个爽点几章）。算出均密度，与本书同口径对比
（对家轮第 3 条直接引用这张表）。

### 7. 节奏样本（连续 5 章）

每章记「阻碍 → 代价 → 回报」三拍的实际字数占比（粗估百分比）。
连看 5 章就能看出对标书的节拍器：它的爽点前置铺垫吃多少字、
回报段落给多少字。写同类章节时按这个占比校准自己的细纲。

## 拆完之后怎么消费

1. **文风对齐**：`check-distribution.py --baseline 对标/{书名}/文风基线.json`
2. **对家轮审稿**：`references/anti-pattern-checklist.md` 第三轮直接引用
   概要/金手指/爽点抽样做同款度与密度对比。
3. **写作前捞参考**：写前必读流程（SKILL 第四节）在「定赛道」「做包装」
   时读 `金手指.md` 与 `爽点抽样.md`；文风基线由门禁自动消费。
4. **节奏校准**：细纲阶段按 `节奏样本` 的三拍占比排每章事件。

## 禁止事项

- 不整段复制对标书原文进库（版权纪律，见文件头）。
- 拆解结论不回写进本书的正文/追踪——对标库只是参考，
  本书事实以 `追踪/_tracking-state.json` 为唯一来源。
- 一本书一份库，不把两本对标书拆进同一个目录。

## 附录：存量书导入与对标拆文命令全量（2026-11-15 自 SKILL.md 第二节迁出）


**存量书冷启动接管**（已有几百章的连载/完本旧稿接进追踪体系）——只回填近
N 章，更早的事实由 recall.py 检索层承接，不重建全量台账：

```bash
S=~/workspace/custom-skills/novel-forge/scripts
# 1) 脚本侧：盘点（章号/断号/字数）+ 本书文风基线 + 回填清单 + init 预填单
python3 $S/import_manuscript.py prepare --project <书目录> --source <原稿目录|单文件> [--recent 20]
# 2) 模型侧：按 .story/import/回填章节清单.md 精读近 20 章，填 init-skeleton.json
#    （八步协议见 .story/import/init-填写说明.md）
# 3) 提交与校验：
python3 $S/tracking_commit.py init --project <书目录> --input .story/import/init-skeleton.json
python3 $S/import_manuscript.py verify --project <书目录>   # TODO 残留/章号对齐/悬置线拦截
python3 $S/forge.py truth --book <书目录> && python3 $S/recall.py index --project <书目录>
```

**对标书拆文**（建剧情模块库）——脚本管统计，模型管语义：

```bash
# 确定性层：文风基线.json + 文风.md + 拆文报告.md（含语义层待办清单）
python3 $S/analyze_book.py --book <对标书目录> --out <书目录>/对标/<书名>
# 语义层（角色卡/剧情线/金手指/爽点抽样）：references/book-teardown.md 七步待办
```

`文风基线.json` 与 human-baseline.json 同 schema。`forge.py dist` 在 `--book`
模式下**自动优先**用 `<书目录>/文风基线.json` 当对比基准（存量书导入时由
prepare 生成）——「像不像这一本」比「像不像人类」灵敏；拆文产物放在
`对标/<书名>/文风基线.json`，需要贴着对标书写时用 `--baseline` 显式指定。
