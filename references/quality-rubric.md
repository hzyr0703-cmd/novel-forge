# 质量评分量规（stop-slop 五维评分的中文网文移植）

**来源**：移植自 [hardikpandya/stop-slop](https://github.com/hardikpandya/stop-slop)
（MIT License）的 Scoring 部分。原文是英文写作的五维 1–10 评分，
本文件按中文网文语境转写。

**定位**：这是**主观质量层**，与机检层互补：
- 机检层（`spec_check.py` / `check-ai-patterns.js` / `check-chinese-tone.py`）
  查可数的东西——字数、对话占比、爽点密度、禁词命中。机检通过 = 不违反规格。
- 本量规查「读起来好不好」。**机器测不了，由你（写作的 agent 或人）按
  定义打分**。打分发生在交付前自查时，不进 `forge.py gate` 自动流程。

**与 gate 的关系**：gate 管硬规格与确定性冲突（阻断）；本量规管软质量
（建议）。总分低于返工线时**建议**重写，不是禁止交付——但如果你自己
读着都过不了 35 分，交出去大概率扑。

---

## 五个维度

各 1–10 分。评分锚点定义如下（10 = 这个维度无可挑剔，1 = 完全失败）：

### 1. 直白（Directness）

**问**：句子是在陈述，还是在宣布？

| 分 | 锚点 |
|----|------|
| 9–10 | 每句都在推进画面或信息，找不到一句「铺垫腔」 |
| 5–6 | 有少量起手式（「说到底」「说白了」）、总结腔（「这意味着」），但整体直接 |
| 1–2 | 通篇绕着说：先立靶再推翻、先感叹再叙述、用冒号提示语替自己说话 |

网文语境：对话直白是人物性格，不算扣分项。只评叙述层。
`check-chinese-tone.py` 的翻案腔/起手式/冒号提示语命中会直接拉低此维。

### 2. 节奏（Rhythm）

**问**：句子长短是有意的，还是节拍器？

| 分 | 锚点 |
|----|------|
| 9–10 | 长短句错落有致，紧张处短句密集，舒缓处长句铺开，段尾收法各不相同 |
| 5–6 | 大体有变化，但同段内连续三四句同档 |
| 1–2 | 节拍器：每句都是「主谓宾，补充说明」同构，或通篇短句堆砌 |

**上游警告（lieflat 实测）**：「AI 句长更均匀」是切句缺陷造成的假象，
句长均匀度人机无差异（R=0.87）。所以这维**不评句长方差**，评的是
**句法结构重复**——相邻句同款由 `check-chinese-tone.py` 机检，此处评
你读起来的感受：连着三句一个模子，你自己读一遍能听出来。

### 3. 可信（Trust）

**问**：它尊重读者的智商吗？

| 分 | 锚点 |
|----|------|
| 9–10 | 信息直接给出，信任读者能接住；不解释刚发生的情节，不预判读者反应 |
| 5–6 | 偶有手把手解释（「也就是说」「换句话说」），但主体克制 |
| 1–2 | 处处怕读者看不懂：刚写完打斗立刻总结谁赢了，刚埋伏笔立刻提示重要性 |

网文语境：**爽点声明与钩子不算不信任**——那是类型契约。扣分的是
**正文里**反复向读者确认「你注意到了吗」。

### 4. 真实（Authenticity）

**问**：像一个活人写的吗？

| 分 | 锚点 |
|----|------|
| 9–10 | 细节有体温：具体的物件、不对称的对话、人物有各自的语言指纹 |
| 5–6 | 整体像人，但配角对话口吻趋同，场景描写偶见套话 |
| 1–2 | 通篇翻译腔/播音腔，人物像同一个人，情绪靠形容词直述 |

注意上游的证伪清单（**不要反向操作**）：比喻、正文设问、句内排比
都是人类用得更多的——**为了「像人」而刻意加这些是帮倒忙**。
这一维评的是整体感受，不靠加减特定修辞凑分。

### 5. 密度（Density）

**问**：有可以删掉而不损失信息的句子吗？

| 分 | 锚点 |
|----|------|
| 9–10 | 删任何一句都损失信息或味道，没有水分 |
| 5–6 | 有少量冗余（重复交代已知信息、形容词堆叠），但主体扎实 |
| 1–2 | 大量注水：同一件事换个说法再说一遍、环境描写与情绪无关地铺满 |

网文语境：**字数达标压力与密度天然冲突**——但灌水被判定的代价
（读者弃书）远高于字数差几百字。宁短勿水。

## 评分纪律

1. **逐维独立打分**，不要先给总分再凑维度。
2. **打分必须给证据**：每维至少指认一处具体文本支撑（最高分和最低分
   同样需要——「我觉得挺好」不算评分）。
3. **双 35 线**：
   - **总分 < 35/50 → 建议返工**。返工时优先改最低分的那个维度，
     而不是全篇重写。
   - **任何一维 ≤ 2 → 该维必须重写**，无论总分多高（一维崩坏
     足以构成弃书理由）。
4. **声明块延伸**（可选）：在章末声明块追加一行 `<!-- quality: 4-7-8-6-7 -->`
   五维分数。工具不解析它，它只是给下一次写章时的你自己看的历史记录。
5. **不要为了凑分改文**。尤其不要按「被证伪清单」的反向操作来提分——
   那些特征人类用得更多，刻意加反而更假。

## 与机检层的分工对照

| 你想检查的 | 用哪个 |
|-----------|--------|
| 章尾钩子有没有、爽点够不够、字数对不对 | `forge.py gate`（机检，阻断） |
| AI 味句式、章尾预告、情绪直述 | `check-ai-patterns.js`（机检，阻断） |
| 翻案腔密度、冒号提示语、段首零回指评论、结构同款 | `check-chinese-tone.py`（机检，advisory） |
| 读起来拖不拖、假不假、像不像填表 | **本量规**（主观，交付前自查） |

机检零命中 + 量规高分 = 可以交付。机检零命中 + 量规低分 = 你写出了
一篇「合规的烂文章」，老老实实返工。
